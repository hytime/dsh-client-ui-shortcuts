# 与官方快捷键的接入

本插件的新版（`0.2.1`）按 DSH `0.2.0-rc.1` 的公开接口设计：**快捷键由官方管理，插件只做快速呼出界面和可选交互增强**。

## 分工

| 能力 | 归属 |
| --- | --- |
| 命令注册、冲突检查、按键录制规则、按键持久化 | 官方 `@deepseek-ai/dsh-client-shortcuts` |
| 快捷键列表与录键界面 | 官方 `@deepseek-ai/dsh-client-ui-shortcuts` |
| 呼出插件的快速面板 | 插件注册一个官方可编辑命令 `hytime.shortcuts.open` |
| 面板内改键 | 插件界面调用官方 `describeBinding()` / `edit()` / `recording()` |
| Question / Approval 增强交互 | 插件提供，**默认关闭**，在面板中手动开启 |

插件不自建按键存储，也不内置第二套快捷键配置。默认键声明在官方命令上：

| 平台 | 默认键 |
| --- | --- |
| Web / macOS | `⌘⌥⇧S` |
| Web / Windows | `Ctrl+Alt+Shift+S` |
| Web / Linux | 不设默认键（官方在该平台的允许集合更窄） |

用户可以在 **DSH 设置 → 通用 → 快捷键** 中修改，也可以在插件快速面板中修改；两处操作的是同一份官方配置，因此在任一处改键都会同步。

## 面板内的改键

面板中的「录入快捷键 / 修改快捷键」按钮：

1. 调用官方 `recording(true)`，让官方在桌面端接管原生按键；
2. 用本地监听收集一个候选组合，忽略 IME 组合与重复按键，纯修饰键按下不计入；
3. 交给官方 `describeBinding()` 规范化并检查保留组合与冲突；
4. 通过校验后调用官方 `edit()`，并携带当前官方 revision 写入。

冲突、不支持、配置已变更、写入失败等都由官方结果分类，面板显示对应说明。`恢复默认` 删除覆盖、`清除` 直接解绑，也都走官方 `edit()`。

## 配置导入导出

面板顶部提供「导出」与「导入」，用于备份、迁移和团队分发。**导入导出不改变快捷键的所有权**：官方仍是键位的唯一存储与校验者。

### 导出

导出的是**完整快捷键快照**：官方目录里的每一条命令都会写入（含未修改的默认项），而不是只导出被改过的条目。

```json
{
  "format": "dsh-client-ui-shortcuts/quick-panel",
  "version": 2,
  "configuration": {
    "questionEnabled": false,
    "approvalEnabled": false,
    "profile": "web:macos",
    "shortcuts": {
      "hytime.shortcuts.open": {
        "modified": false,
        "binding": { "code": "KeyS", "modifiers": ["alt", "shift", "meta"] },
        "label": "打开快速面板",
        "keys": ["⌥", "⇧", "⌘", "S"]
      },
      "session.new": {
        "modified": true,
        "binding": { "code": "KeyJ", "modifiers": ["shift", "meta"] }
      }
    }
  }
}
```

- `shortcuts` 覆盖当前设备 profile 的全部命令，按命令 ID 稳定排序，因此同一配置两次导出逐字节一致；
- `binding` 为 `null` 表示该命令无键（显式清除）；`modified` 记录该命令是否覆盖了官方默认；
- `label` 与 `keys` 仅供人阅读，导入时忽略；
- 逻辑修饰键 `primary` 会经官方 `describeBinding()` 归一化为设备明确的 `meta`/`control`，保证文件在其他设备可重现；官方无法描述的历史绑定会被跳过而不会导致整个导出失败。

### 导入

1. **严格校验**：`format`、`version`、字段集合、命令 ID（官方规则）、物理键编码、修饰键都必须合法；未知字段、错误类型、更高版本**整体拒绝**，不做部分读取；上限 1 MiB、命令数上限 1024；
2. 逐条经官方 `describeBinding()` 与 `edit()` 写入，写入前先检查官方拒绝与冲突；
3. 按 `modified` 决定动作，避免把默认项固化：

| 文件中的 `modified` | 当前状态 | 导入动作 |
| --- | --- | --- |
| `true` | — | 写入覆盖（`binding: null` 即清除） |
| `false` | 已有覆盖 | `reset`，恢复官方默认 |
| `false` | 未修改 | 不写入 |

4. 本组合未挂载的命令会被跳过（官方拥有「哪些命令存在」的事实）；
5. 导入按**目标快照**整体规划：先释放本文件将要移动或清除的键，再写回目标值，因此两条命令互换绑定、或同一文件把某键从一个命令转给另一个命令都能正确恢复；
6. 两个增强开关通过一次官方 `mutate()` 原子写入，不会只写一半；
7. 官方 `edit()` 是逐条接口，**没有批量事务**。若中途被官方拒绝或写入失败，插件会按导入前快照尽力回滚；回滚后仍未恢复的命令会明确列出（「部分快捷键未能恢复」），不会谎报导入成功。需要「任何失败都绝无中间状态」时必须由 DSH 官方提供批量事务接口。

失败原因分别提示：文件无效、版本过新（需升级插件）、文件过大、无法读取、官方不支持该组合、与官方命令冲突、写入失败。版本 1 的旧文件仍可导入，视为对插件呼出命令的单条覆盖。

### 往返一致性

在官方接受全部写入的前提下，导入后再导出会得到同样的完整快照，可以把文件当作当前键盘配置的权威快照用于版本管理或团队分发。若面板提示「部分快捷键未能恢复」，请以官方快捷键设置为准并重新导出。

## 可选交互增强

两个开关都默认关闭，关闭时不注册任何 composer 替换，直接使用 DSH 官方界面：

- **增强 Question 交互**：方向键选择、`Enter` 确认、`Escape` 取消任务；
- **增强 Approval 交互**：键盘选择允许一次或拒绝。开启此功能**不会**自动授权。

开关保存在插件自己的配置中，只影响是否接管对应交互卡片。Esc 取消、空绑定关闭默认值等边界见 `tests/composer.client.spec.tsx`。

## 兼容声明

- 插件版本 `0.2.1`，已验证基线为 DSH `0.2.0-rc.1`。
- `peerDependencies` 为 `>=0.2.0-rc.1 <1.0.0`：接受已验证基线**及其之后的更高版本**（`0.2.0-rc.2`、`0.2.0`、`0.2.1`、`0.3.0-*` 等预发布），拒绝更低的旧版与 `1.0.0` 起。DSH 按 `evaluatePluginCompatibility` 校验，且**预发布参与范围判断**——区间里写出 `0.2.0-rc.1` 这个预发布元组，后续 minor 的预发布版才会解析。不匹配时安装会给出明确提示与精确豁免方式。
- `devDependencies` 仍精确固定 `0.2.0-rc.1`：peer 决定“能装到哪些版本”，devDependency 决定“用哪个版本编译与类型检查”。被接受只是加载门槛，不等于已逐版本验收；新版本仍应先在真实 composition 中验证。
- 新版**不再兼容旧版 DSH**：已移除 `settingsScope`、旧 Connection settings API、`settings.plugin.item` 坐席、旧 sessions 摘要读取、旧 question/approval payload 适配，以及插件自建方案与键位存储。旧版本用户请继续使用 `0.1.x`。
- 旧配置不会自动写入官方按键配置；`0.1.x` 的 `activeProfile`、`customProfiles` 等字段在新版被忽略。

## 验收

```bash
pnpm run typecheck
pnpm run bundle
pnpm exec vitest run tests
```

自动化测试覆盖官方命令注册、面板改键仅走官方 `edit()`、录制开关、失败分类、两个开关默认关闭与独立启停、旧载体拒绝、以及卸载时的注册与订阅清理。

浏览器验收应在装有 `0.2.0-rc.1` 的真实 DSH Web composition 中进行：确认插件行进入 boot graph、官方快捷键列表出现「打开快速面板」、在面板改键后官方设置同步、关闭两个开关时回到官方 Question/Approval 界面、控制台无报错。安装新版本后需要重新加载 Web composition，已打开的页面不会热更新。
